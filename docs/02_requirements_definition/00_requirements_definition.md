# 要件定義案

## 1. 目的

本書は、Data Center Asset & Infrastructure Manager の初期開発に向けた要件定義案を整理するものである。

本システムは、データセンター、ラック、機器、IPサブネット、保守契約、ユーザー、プラン情報を一元管理し、インフラ資産管理業務の効率化を目的とする。

## 2. 前提条件

| 項目 | 内容 |
|---|---|
| 開発手法 | ウォーターフォール |
| 設計方針 | DDDを意識した設計 |
| アプリ形態 | Webアプリケーション / SaaS |
| バックエンド | Java / Spring Boot |
| 認証・認可 | Spring Security |
| UI | Vaadin |
| DB | MariaDB |
| ビルド | Maven |
| 補助ライブラリ | Lombok |
| 開発支援 | OpenClaw |

## 3. システム利用者

| 利用者 | 説明 |
|---|---|
| システム管理者 | 全体設定、プラン、テナント管理を行う |
| テナント管理者 | 自社テナント内のユーザー、契約確認、権限、DC、機器などを管理する |
| 契約管理者 | 自社テナントの契約プラン、利用状況、オプション契約を確認・申請・管理する。ユーザー・運用データの管理は行わない |
| 運用管理者 | 自社テナント内のマスタ、ロケーション、ラック、機器、IP、保守契約を管理する。ユーザー・契約管理は行わない |
| 編集者 | 自社テナント内のマスタ、機器、IP、保守契約を登録・更新できるが、契約・ユーザー・権限管理は行わない |
| 閲覧者 | 登録済み情報の参照のみ行う |
| 監査担当者 | 保守状況、棚卸、操作履歴を閲覧する |

- 連絡先管理

## 5. プラン要件

### 5.1 プラン一覧

本節では代表的な上限のみを示す。プラン制限の正本は `03_pricing_plan_limits.md` とし、タグ数、CSVインポート行数、操作履歴保存期間、オプション適用条件は同資料を参照する。

| プラン | 利用形態 | DC上限 | ラック上限 | 機器上限 | IP数上限 | ユーザー上限 |
|---|---|---:|---:|---:|---:|---:|
| Free | 14日間トライアル | 1 | 3 | 40 | 256 | 3 |
| Starter | 月額 / 年額 | 2 | 5 | 50 | 512 | 3 |
| Business | 月額 / 年額 | 5 | 50 | 100 | 1,024 | 10 |
| Enterprise | 個別契約 | 10 | 100 | 1000 | 2,048 | 30 |

### 5.2 Freeプラン方針

- Freeプランは14日間のトライアル利用を目的とする。
- 小規模ながら現実的な評価ができるよう、DC 1件、ラック3本、機器40台、管理対象IP 256件、タグ10件、ユーザー3名まで登録可能とする。
- トライアル終了後も継続利用する場合は、有料プランへの移行を促す。

### 5.3 オプション要件

| オプション | 単位 | 内容 |
|---|---:|---|
| IP上限追加 | 256IP単位 | 管理対象IP数上限に256件を加算する |
| 機器追加 | 100台単位 | プラン上限に加算する |

### 5.4 上限制御

- 各テナントは契約プランに応じた上限を持つ。
- 上限を超えるデータ登録は不可とする。
- オプション契約がある場合は、基本上限にオプション分を加算する。
- 上限到達時は、登録画面で理由を表示する。
- 論理削除済みデータは通常の上限カウント対象外とする。

## 6. 機能要件

本章の `RQ-xxx` は要件本文の整理番号とし、後続設計・ユースケースで参照する正式な機能IDは `01_function_list.md` の `F-xxx` を正本とする。

## RQ-001 認証機能

### 概要

ユーザーがメールアドレスとパスワードでログインできる。

### 要件

- ログインできること。
- ログアウトできること。
- 未ログインユーザーは管理画面にアクセスできないこと。
- パスワードを忘れた場合、登録メールアドレス宛の再設定メールから新しいパスワードを設定できること。
- 管理者はユーザー詳細からパスワード再設定メールを再送できること。
- ユーザー招待時は招待メールを送信し、招待対象者が初回パスワードを設定して利用開始すること。
- 招待トークンは有効期限付き・一度限り利用とし、期限切れ時は管理者が再招待できること。
- パスワード再設定トークンは有効期限付き・一度限り利用とし、画面上でメールアドレス存在有無を推測できないこと。
- パスワードはハッシュ化して保存すること。

## RQ-002 テナント管理機能

### 概要

SaaS利用単位としてテナントを管理する。

### 要件

- テナントを登録、編集、削除できること。
- テナントごとに契約プランを設定できること。
- テナントごとにデータを分離すること。
- 他テナントのデータは閲覧・更新できないこと。

## RQ-003 ユーザー管理機能

### 概要

テナント内の利用者を管理する。

### 要件

- ユーザーを招待、編集、無効化できること。
- 初期ユーザー作成は招待メール方式を基本とし、管理者が平文の初期パスワードを設定しないこと。
- 招待中、招待期限切れ、有効、無効の状態を管理できること。
- 招待取消・再招待ができること。
- ユーザー数上限は招待送信時に有効ユーザーと招待中ユーザーを含めて判定すること。
- テナント初期作成時に登録される初期テナント管理者は、通常のユーザー無効化・削除対象にできないこと。
- 初期テナント管理者を利用停止扱いにする場合は、テナント解約フローでのみ実施できること。
- ユーザーにロールを設定できること。
- プラン上限を超えるユーザー招待・登録はできないこと。

## RQ-004 データセンター管理機能

### 概要

データセンターの基本情報を管理する。

### 管理項目

- データセンター名
- 正式名称
- 呼称名・別名
- 地域
- 都道府県
- 住所
- 備考
- タグ

### 要件

- データセンターを登録、編集、削除できること。
- 連絡先を紐づけられること。
- プラン上限を超える登録はできないこと。

## RQ-005 連絡先管理機能

### 概要

データセンターや保守契約に関連する連絡先を管理する。

### 管理項目

- 会社名
- 部署名
- 担当者名
- メールアドレス
- 電話番号
- 備考

### 要件

- 連絡先を別エンティティとして管理すること。
- データセンター、保守契約などに紐づけられること。

## RQ-006 ロケーション階層管理機能

### 概要

データセンター内の物理的な配置階層を管理する。棟、フロア、エリア、ラック列は初期リリースから必須の階層として扱う。

### 対象

- 棟
- フロア
- エリア
- ラック列
- ラック

### 要件

- データセンター配下に棟を登録できること。
- 棟配下にフロアを登録できること。
- フロア配下にエリアを登録できること。
- エリア配下にラック列を登録できること。
- ラック列配下にラックを登録できること。
- エリアには東・西・南・北などの区分を設定できること。
- フロア図は行・列のグリッドで表現し、エリア、ラック列、ラック位置を視覚的に把握できること。
- 初期リリースでは自由配置・3D表示ではなく、棚卸や配置確認に使える簡易な2Dグリッド表示を基本とすること。

## RQ-007 ラック管理機能

### 概要

ラックの基本情報、搭載可能U数、設置場所を管理する。

### 管理項目

- ラック名
- 正式名称
- 呼称名・別名
- ラック列
- 高さ
- 備考
- タグ

### 要件

- ラックを登録、編集、削除できること。
- ラック高さを管理できること。
- プラン上限を超えるラック登録はできないこと。
- ラックテンプレートを登録、編集、複製、無効化できること。
- ラックテンプレートからラックを作成できること。
- テンプレートにはラック高さ、用途、標準搭載構成、予約U範囲を保持できること。
- テンプレート適用は作成時コピーを基本とし、既存ラックへ自動反映しないこと。
- ラック図はU単位の縦グリッドで表現し、搭載機器、空きU、利用中Uを視覚的に把握できること。
- 機器の搭載開始U・搭載U数に基づき、グリッド上で重複搭載を確認できること。

## RQ-008 機器管理機能

### 概要

サーバー、ネットワーク機器などを管理する。

### 対象機器

- サーバー
- スイッチ
- ルーター
- ファイアウォール
- ロードバランサー
- その他機器

### 管理項目

- 機器名
- 正式名称
- 呼称名・別名
- 機器種別
- メーカー
- 型番
- シリアル番号
- 設置ラック
- 搭載開始U
- 搭載U数
- ステータス
- 備考
- タグ

### 要件

- 機器を登録、編集、削除できること。
- 機器に複数の呼称名・別名・略称・運用名を登録できること。
- 機器に複数のタグを付与・解除できること。
- 機器一覧・横断検索で、正式名称、代表表示名、別名、タグを検索対象にできること。
- ラックに紐づけられること。
- IPアドレスを紐づけられること。
- 保守契約を紐づけられること。
- プラン上限を超える機器登録はできないこと。
- 保守契約が未紐づけの機器を検索できること。

## RQ-009 IPサブネット管理機能

### 概要

IPサブネットと配下のIP利用状況を管理する。

### 管理項目

- IPサブネット
- CIDR
- ネットワーク区分
- 利用状態
- 紐づけ機器
- 用途
- 備考
- タグ

### 要件

- IPサブネットを登録、編集、削除できること。
- 初期対応はIPv4サブネットを主対象とし、IPv6はサブネット情報の登録と明示登録された個別IPの管理までを対象とすること。
- IPv6サブネット配下の全IP自動生成は初期対象外とすること。
- サブネット配下の個別IP利用状況を機器に紐づけられること。
- 未使用IPを検索できること。
- IPサブネット数には上限を設けない。ただし、サブネット登録・個別IP生成・明示登録により管理対象IP数上限を超える場合は登録できないこと。
- オプション契約により管理対象IP数上限を追加できること。

### 概要

### 管理項目

- 保守終了60日前、30日前、当日、期限切れを通知対象として抽出できること。
- 期限状態は契約終了日から自動算出し、更新状態と合わせて検索できること。

## 7. 非機能要件

## NF-001 セキュリティ

- テナント間のデータ分離を行うこと。
- パスワードは平文保存しないこと。
- 認証済みユーザーのみ管理画面へアクセスできること。
- ロールに応じて操作権限を制御できること。

### NF-001A 認証・セッション・Webセキュリティ方針

- ログイン試行制限を設け、連続失敗時は一時ロックまたは段階的遅延を行う。
- パスワードは長さ・複雑性・漏えい済み文字列回避を含むポリシーを定義し、平文をDB・ログ・通知に残さない。
- セッションは一定時間の無操作で失効し、Cookieには `HttpOnly`、`Secure`、`SameSite` を設定する。
- Vaadin/Spring SecurityのCSRF対策を有効化し、URL直打ち・直接API呼び出しもService層で認可する。
- 監査ログは一般利用者が改ざんできない権限で保存し、管理者操作も操作履歴へ記録する。

## NF-002 性能

- 一覧画面は通常利用時に実用的な速度で表示できること。
- 検索条件に応じたDBインデックスを設計すること。
- 将来的なデータ増加を考慮すること。

## NF-003 可用性

- 単一障害点を最小化できる構成を検討すること。
- 初期開発では小規模SaaSとして運用可能な構成を優先すること。

## NF-004 保守性

- DDDを意識し、ドメインごとに責務を分離すること。
- Java / Spring Boot / Vaadin の標準的な構成を採用すること。
- OpenClawでレビューしやすいよう、命名規則と設計ルールを統一すること。

## NF-005 拡張性

- クラウドリソース管理を後から追加できること。
- プランやオプションを追加しやすい構造にすること。
- 外部API連携を将来的に追加できること。

## NF-006 監査性

- 初期開発から主要エンティティに最低限の監査情報を保持すること。
  - 作成者
  - 作成日時
  - 更新者
  - 更新日時
- 初期開発では最低限監査情報に加えて操作履歴を保存すること。変更差分を詳細に保持する完全な変更履歴は将来拡張とすること。
- 操作履歴は登録、更新、削除、ログイン失敗、ユーザー招待、権限変更、プラン変更を初期対象とすること。CSVインポートの操作履歴は初期追加対応時に対象へ追加すること。
- 操作履歴の保存期間は `03_pricing_plan_limits.md` のプラン別定義に従うこと。

## 12. 業務ルール案

| ルールID | 内容 |
|---|---|
| BR-001 | テナントごとにデータを分離する |
| BR-002 | プラン上限を超える登録は不可 |
| BR-003 | IP上限追加オプションは256IP単位 |
| BR-004 | 機器追加オプションは100台単位 |
| BR-005 | Freeプランは14日間トライアルとし、DC 1件、ラック3本、機器40台、管理対象IP 256件、タグ10件、ユーザー3名まで。IPサブネット数には上限を設けない |
| BR-006 | 保守契約終了日の60日前、30日前、当日、期限切れを通知対象 |
| BR-007 | 機器は0個以上のIPアドレスを紐づけ可能 |
| BR-008 | 保守契約は複数機器を対象にできる |
| BR-009 | 正式名称以外に複数の呼称名・別名を持てる |
| BR-010 | 各管理対象に複数タグを付与できる |
| BR-011 | フロア図は行・列の2Dグリッド、ラック図はU単位の縦グリッドで表現する。高度な自由配置・3D表示は初期対象外 |
| BR-012 | 削除は原則として論理削除とし、削除済みデータは通常検索・上限カウントから除外する。復元は初期対象外 |
| BR-013 | 論理削除後の再登録は、テナント内で業務上一意性が必要な識別子（ユーザーメールアドレス、有効IPアドレス、機器シリアル番号、契約番号など）は削除済みデータを含めて重複チェックする。ただし名称・表示名は削除済みデータと同一でも再登録可能とし、監査・操作履歴上は別レコードとして追跡する |
