# 外部連携要件

## 1. 前提

本資料は、DCIMにおける外部連携要件を整理したものです。  
初期リリースではCSVエクスポートとメール通知を必須対応とし、CSVインポートは初期追加対象として優先的に対応します。AWS API連携やSlack / Teams / Webhookなどの外部通知連携は段階的に実装する方針とします。

## 2. 外部連携一覧

| 連携ID | 連携名 | 連携方式 | 概要 | 優先度 |
|---|---|---|---|---|
| EXT-001 | CSVインポート | ファイル取込 | 機器、IP、ラック、保守契約などをCSVで一括登録する | 重要 |
| EXT-002 | CSVエクスポート | ファイル出力 | 管理データをCSVで出力する | 必須 |
| EXT-003 | AWSアカウント手動登録 | 画面入力 | AWSアカウント、リージョンを手動登録する | 任意 |
| EXT-004 | AWS API連携 | API | AWSリソース情報をAPIで取得する | 任意 |
| EXT-005 | メール送信 | SMTP / メールサービス | 招待、保守期限、上限到達をメール通知する | 必須 |
| EXT-006 | Slack通知 | Webhook | 保守期限やエラーをSlackに通知する | 任意 |
| EXT-007 | Microsoft Teams通知 | Webhook | 保守期限やエラーをTeamsに通知する | 任意 |
| EXT-008 | Webhook連携 | HTTP | 外部システムにイベント通知する | 任意 |
| EXT-009 | 認証連携 | OAuth / SAML | 外部IdPと連携する | 将来検討 |

## 3. CSVインポート要件

CSVインポートは初期追加対象とし、初期リリース後の早期対応を前提に詳細化します。

### 3.1 対象データ

| CSV-ID | 対象 | 概要 | 優先度 |
|---|---|---|---|
| CSV-IN-001 | データセンター | DC名、別名、所在地、連絡先など | 重要 |
| CSV-IN-002 | ラック | DC、棟、フロア、エリア、ラック列、ラック番号など | 重要 |
| CSV-IN-003 | 機器 | 機器名、別名、タグ、種別、メーカー、型番、シリアル、ラック位置など | 重要 |
| CSV-IN-004 | IPサブネット / IP利用状況 | サブネット、CIDR、IP、状態、紐づき機器など | 重要 |
| CSV-IN-005 | 保守契約 | 契約名、契約先、期間、対象機器など | 重要 |
| CSV-IN-006 | クラウドリソース | AWSアカウント、リージョン、EC2など | 任意 |

### 3.2 取込仕様

| 項目 | 仕様 |
|---|---|
| 文字コード | UTF-8を基本とする |
| ヘッダー行 | 必須 |
| 区切り文字 | カンマ |
| 取込方式 | 新規登録、更新、エラー検出を行う |
| エラー処理 | 行単位でエラー内容を表示する |
| 上限チェック | プラン上限を超える取込はエラーとする |
| 重複チェック | 名称、シリアル、IPアドレスなどで重複チェックする |
| 取込履歴 | 実行者、実行日時、件数、エラー件数を保存する |

## 4. CSVエクスポート要件

CSVエクスポートは初期リリース必須とします。棚卸、監査、既存台帳との並行運用に利用できるようにします。

| CSV-ID | 対象 | 出力内容 | 優先度 |
|---|---|---|---|
| CSV-OUT-001 | データセンター一覧 | DC、所在地、連絡先、タグ | 重要 |
| CSV-OUT-002 | ラック一覧 | DC、棟、フロア、エリア、ラック列、ラック番号 | 重要 |
| CSV-OUT-003 | 機器一覧 | 機器名、別名、タグ、種別、設置場所、IP、保守状態 | 重要 |
| CSV-OUT-004 | IPサブネット / IP利用状況一覧 | サブネット、CIDR、IP、状態、紐づき機器 | 重要 |
| CSV-OUT-005 | 保守契約一覧 | 契約名、契約先、期間、対象機器、期限状態 | 重要 |
| CSV-OUT-006 | 保守未加入機器一覧 | 保守契約が紐づいていない機器 | 必須 |
| CSV-OUT-007 | 保守期限接近一覧 | 期限切れ、30日以内、60日以内の契約 | 必須 |

## 5. AWS連携要件

## 5.1 手動登録

クラウドリソース管理は将来拡張とし、初期リリースでは物理DCIM機能を優先します。AWS API連携を行う前段階として、将来的に手動登録を検討します。

| 項目 | 内容 |
|---|---|
| AWSアカウント | アカウントID、アカウント名、用途、タグ |
| AWSリージョン | リージョンコード、表示名 |
| EC2 | インスタンスID、名称、状態、プライベートIP、パブリックIP、タグ |
| コンテナ | クラスタ名、サービス名、タスクまたはコンテナ名 |
| EKS Pod | クラスタ名、Namespace、Pod名、状態 |

## 5.2 API連携

| 項目 | 内容 |
|---|---|
| 認証方式 | IAM Role、アクセスキー、外部IDなどを検討 |
| 取得対象 | EC2、EKS、コンテナ、タグ、IP情報 |
| 同期方式 | 手動同期、定期同期を検討 |
| 同期履歴 | 実行日時、成功件数、失敗件数、エラー内容を保存する |
| データ上書き | 手動編集項目とAPI取得項目の優先順位を定義する |
| 権限 | 読み取り専用権限を原則とする |

## 6. メール連携要件

| 項目 | 内容 |
|---|---|
| 利用目的 | ユーザー招待、保守期限通知、上限通知、エラー通知 |
| 送信方式 | SMTPまたは外部メール送信サービス |
| 送信先 | ユーザー、ロール、個別メールアドレス |
| テンプレート | 件名、本文をテンプレート化する |
| 送信履歴 | 送信日時、送信先、通知種別、結果を保存する |
| 再送 | 失敗時の再送要否を検討する |

## 7. Slack / Teams / Webhook連携要件

| 項目 | 内容 |
|---|---|
| 連携方式 | Incoming Webhookを基本とする |
| 通知対象 | 保守期限、期限切れ、上限到達、取込エラー |
| 設定単位 | テナント単位を基本とする |
| 有効化 | 管理者のみ設定可能 |
| セキュリティ | Webhook URLは暗号化または秘匿管理する |
| 初期対応 | 将来拡張扱い |

## 8. 認証連携要件

| 項目 | 内容 |
|---|---|
| 対象 | Google Workspace、Microsoft Entra ID、SAML IdPなど |
| 優先度 | 将来検討 |
| 初期対応 | 通常ログイン、メール招待方式を優先 |
| 備考 | Enterprise向け機能候補 |

## 9. セキュリティ要件

| 項目 | 要件 |
|---|---|
| 外部認証情報 | APIキー、Webhook URL、SMTP認証情報は平文保存しない |
| 権限最小化 | AWS連携は読み取り専用権限を原則とする |
| 最低限監査情報 | 外部連携設定に作成者、作成日時、更新者、更新日時を保持する |
| 操作履歴 | 外部連携設定の作成、更新、削除履歴は将来拡張として検討する |
| 連携失敗時 | エラー内容を管理者に通知する |
| テナント分離 | 他テナントの連携設定、取得データにアクセスできないようにする |

## 10. 初期リリース範囲

| 区分 | 対象 |
|---|---|
| 初期リリース必須 | メール通知、CSVエクスポート、保守未加入・期限接近一覧の出力 |
| 初期追加 | CSVインポート |
| 将来拡張 | AWSアカウント・EC2の手動登録、AWS API連携、Slack / Teams通知、Webhook連携、外部認証連携 |
