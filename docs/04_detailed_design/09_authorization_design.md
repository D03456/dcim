# 4. 詳細設計 - 認可制御設計

## 1. 目的

本書は、本システムの認可制御、ロール判定、テナント分離、Freeトライアル期限超過時の制御を定義する。

## 2. 基本方針

- 画面表示制御とService層の業務認可を両方実施する。
- 最終的な防御線はApplication Service層とする。
- すべての業務データはログインユーザーの `tenant_id` で分離する。
- テナント状態による制御は通常ロールより前に判定する。

## 3. ロール

初期リリースのロールは要件・基本設計の7ロールを正とする。

| ロール | 概要 |
|---|---|
| ROLE_SYSTEM_ADMIN | システム管理者。SaaS全体のテナント登録・編集・解約、システム管理を行う |
| ROLE_TENANT_ADMIN | テナント管理者。テナント内のユーザー、権限、全データを管理できる |
| ROLE_BILLING_ADMIN | 契約管理者。契約プラン、利用状況、オプション、プラン変更申請を管理できる |
| ROLE_OPERATION_ADMIN | 運用管理者。DC、ラック、機器、IP、保守契約を登録・編集できる |
| ROLE_EDITOR | 編集者。運用データの登録・更新ができるが、ユーザー/契約/権限管理はできない |
| ROLE_VIEWER | 閲覧者。登録データを閲覧できる |
| ROLE_AUDITOR | 監査担当者。操作履歴・監査対象情報を閲覧できる |

`ROLE_OPERATOR` は使用しない。運用者相当の権限は `ROLE_OPERATION_ADMIN` と `ROLE_EDITOR` に分ける。

## 4. 認可チェックポイント

| 層 | チェック内容 |
|---|---|
| Vaadin View | メニュー表示、ボタン活性、画面遷移可否 |
| Application Service | 操作権限、テナント分離、テナント状態、プラン上限 |
| Repository | `tenant_id` と `deleted=false` を検索条件に含める |
| DB | 必須制約、一意制約、必要な外部キー |

| 登録 | × | ○ | × | ○ | ○ | × | × |
| 更新 | × | ○ | × | ○ | ○ | × | × |
| 削除 | × | ○ | × | ○ | △ | × | × |

△は対象画面・対象テナントに限定して許可する。

### 権限マスタ

詳細テーブル定義の `permission` / `role_permission` を標準ロール権限の正本とし、Service層ではPermission Service経由で判定する。画面表示制御だけに依存しない。

## 6. テナント状態による制御

| 状態 | 説明 | 許可方針 |
|---|---|---|
| ACTIVE | 通常利用中 | ロールに応じて許可 |
| SUSPENDED | 利用停止中 | 原則ログイン不可または管理者案内のみ |
| TRIAL_EXPIRED | Freeトライアル期限超過 | 参照、CSVエクスポート、プラン変更のみ許可 |
| CANCELLED | 解約済み | 原則ログイン不可 |

## 7. TRIAL_EXPIRED 制御

Freeトライアル期限超過時は、通常ロールより前にテナント状態を判定する。

| 操作 | 可否 | 備考 |
|---|:---:|---|
| ログイン | ○ | 期限超過バナーを表示 |
| 参照 | ○ | 既存データ確認のため許可 |
| CSVエクスポート | ○ | データ退避・棚卸のため許可 |
| 契約プラン確認 | ○ | アップグレード導線を表示 |
| 有料プラン変更 | ○ | 継続利用のため許可 |
| 登録・更新・削除 | × | テナント管理者・運用管理者でも不可 |
| CSVインポート | × | 新規データ追加扱い |
| ユーザー招待 | × | テナント拡張扱い |
| オプション追加のみの購入 | × | 有料プラン変更を先に求める |

## 8. Permission Service

認可判断は以下のようなServiceに集約する。

| メソッド | 概要 |
|---|---|
| `canView(user, resource)` | 参照可否 |
| `canEdit(user, resource)` | 登録・更新可否 |
| `canDelete(user, resource)` | 削除可否 |
| `canExportCsv(user, target)` | CSV出力可否 |
| `canImportCsv(user, target)` | CSV取込可否 |
| `ensureTenantAccessible(user, tenantId)` | テナント分離チェック |
| `ensureTenantWritable(user)` | テナント状態を含む更新可否チェック |

## 9. 実装注意

- URL直打ち、API直接呼び出しでもService層で必ず拒否する。
- 他テナントIDがDTOに含まれても、ログインユーザーのtenantIdを優先する。
- 権限不足時は内部情報を表示せず、日本語の業務エラーメッセージを返す。
- 操作履歴は初期必須として `audit_log` に保存する。`created_by` / `updated_by` は主要テーブルの最低限監査情報として併用する。
