# 4. 詳細設計 - テスト設計

## 1. 目的

本書は、本システムの実装時に必要なテスト分類、重点観点、完了基準を定義する。

## 2. テスト分類

| 分類 | 対象 | 主な観点 |
|---|---|---|
| Unit Test | Value Object、Domain Service | 入力制約、状態遷移、境界値 |
| Application Service Test | ユースケース | 権限、テナント分離、上限、トランザクション |
| Repository Test | JPA Repository | tenant_id条件、deleted=false、一意制約 |
| Integration Test | DB、メール、CSV | 実DB接続、通知ログ、CSV履歴 |
| Vaadin UI Test | 画面 | 画面遷移、ボタン制御、エラー表示 |
| Batch Test | Scheduler処理 | 期限通知、Free期限超過、失敗継続 |

## 3. 重点テスト観点

## 3.1 テナント分離

- 他テナントのデータを参照できないこと。
- DTOで他テナントIDを指定しても無視または拒否されること。
- Repository検索に `tenant_id` と `deleted=false` が含まれること。

## 3.2 権限

- 閲覧者は登録・更新・削除できないこと。
- 契約管理者は契約関連のみ操作できること。
- テナント管理者のみユーザー招待・通知設定変更ができること。

## 3.3 Freeトライアル期限超過

- `TRIAL_EXPIRED` でもログイン・参照・CSVエクスポートできること。
- 登録・更新・削除・CSVインポート・ユーザー招待が拒否されること。
- 有料プラン変更は可能であること。
- 更新不可時に適切な日本語メッセージが表示されること。

## 3.4 プラン上限

- DC、ラック、機器、IPサブネット、タグ、ユーザーの上限を超える登録が拒否されること。
- サブネット追加、機器追加のオプションが上限に反映されること。
- 論理削除済みデータはカウント対象外であること。

## 3.5 IP管理

- CIDR重複が拒否されること。
- 個別IPが所属サブネット範囲内であること。
- 使用中IPの二重割当ができないこと。

## 3.6 ラック配置

- U位置の範囲外指定が拒否されること。
- 同一ラック内でU位置が重複しないこと。
- ラック高さ変更時に既存機器を下回る値が拒否されること。

## 3.7 通知

- 保守期限60日前通知が対象になること。
- Free期限3日前・期限日通知が対象になること。
- 同一対象・同一宛先への重複通知が抑止されること。
- メール送信失敗時にFAILEDとして記録されること。

## 3.8 CSV

- CSVエクスポートが権限・検索条件・テナント分離を反映すること。
- CSVインポートでヘッダ不正、必須欠落、形式不正、参照なし、上限超過が検出されること。
- 行単位エラーが `csv_import_error` に保存されること。

## 4. テストデータ方針

- 複数テナントを用意し、テナント分離を検証する。
- Free / Starter / Business / Enterprise の各プランを用意する。
- 期限前、期限日、期限超過のFreeテナントを用意する。
- 権限別ユーザーを用意する。
- ラックU重複、CIDR重複、保守期限などの境界データを用意する。

## 5. 完了基準

- 主要Application Serviceの正常系・異常系がテストされていること。
- 権限、テナント分離、Free期限超過制御のテストがあること。
- Repositoryのtenant_id / deleted条件が検証されていること。
- バッチ、通知、CSVの主要ケースが検証されていること。
- `git diff --check`、ビルド、テストが成功していること。
