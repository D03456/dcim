# 4. 詳細設計 - 通知処理仕様

## 1. 目的

本書は、Data Center Asset & Infrastructure Manager における通知処理の仕様を定義する。

主な対象は、保守契約期限切れ前通知、プラン上限警告、システム通知である。

## 2. 通知種別

| 通知種別 | コード | 概要 | 初期状態 |
|---|---|---|---|
| 保守期限通知 | MAINTENANCE_EXPIRY | 保守契約終了前に通知する | 有効 |
| プラン上限警告 | PLAN_LIMIT | 使用量が上限に近づいた場合に通知する | 有効 |
| システム通知 | SYSTEM | 管理者向けのお知らせ | 有効 |

## 3. 通知チャネル

初期リリースではメール通知を基本とする。

| チャネル | 対応方針 |
|---|---|
| メール | 初期対応 |
| 画面内通知 | 将来対応 |
| Slack / Teams | 将来対応 |
| Webhook | 将来対応 |

## 4. 通知対象者

| 通知種別 | 対象者 |
|---|---|
| 保守期限通知 | テナント管理者、保守担当連絡先、機器担当者 |
| プラン上限警告 | テナント管理者 |
| システム通知 | テナント管理者 |

## 5. 保守期限通知仕様

## 5.1 概要

保守契約の終了日が近づいた場合、対象テナントの管理者または設定された連絡先へ通知する。

標準は「保守切れ2か月前」、つまり60日前通知とする。

## 5.2 抽出条件

| 条件 | 内容 |
|---|---|
| notification_enabled | true |
| deleted | false |
| end_date | 現在日付以降 |
| 通知対象日 | `end_date - notification_days_before <= 現在日付` |
| 重複送信 | 同一対象・同一通知種別・同一宛先に送信済みでない |

## 5.3 標準通知タイミング

| タイミング | 内容 |
|---|---|
| 60日前 | 標準通知 |
| 30日前 | 将来オプション |
| 7日前 | 将来オプション |
| 当日 | 将来オプション |

## 5.4 処理フロー

```text
1. スケジューラが日次で起動
2. 有効なテナントを取得
3. テナントごとの通知設定を取得
4. 保守期限が近い契約を抽出
5. 対象契約に紐付く機器を取得
6. 通知先を決定
7. 重複通知済みでないか確認
8. 通知ログをPENDINGで作成
9. メール送信
10. 成功時はSENT、失敗時はFAILEDに更新
```

## 5.5 通知文面例

### 件名

```text
【DCIM】保守契約期限が近づいています：{contractName}
```

### 本文

```text
以下の保守契約の期限が近づいています。

契約名：{contractName}
保守ベンダー：{vendorName}
契約番号：{contractNumber}
契約終了日：{endDate}
対象機器数：{deviceCount}

対象機器：
{deviceList}

必要に応じて、保守更新または機器の確認を行ってください。
```

## 6. プラン上限警告通知仕様

## 6.1 概要

テナントの利用量が契約プラン上限に近づいた場合、管理者へ通知する。

## 6.2 警告条件

| 対象 | 通知条件 |
|---|---|
| データセンター | 使用率80%以上 |
| ラック列 | 使用率80%以上 |
| 機器 | 使用率80%以上 |
| IPサブネット | 使用率80%以上 |
| ユーザー | 使用率80%以上 |

## 6.3 通知抑止

- 同一対象のプラン上限警告は、原則1日1回までとする。
- 使用率が90%、100%に到達した場合は別レベルの通知を検討する。

## 7. 通知設定

## 7.1 notification_setting

| 項目 | 内容 |
|---|---|
| tenant_id | テナントID |
| notification_type | 通知種別 |
| enabled | 通知有効フラグ |
| email_enabled | メール有効フラグ |
| days_before | 期限前日数 |

## 7.2 初期設定

| 通知種別 | enabled | email_enabled | days_before |
|---|:---:|:---:|---:|
| MAINTENANCE_EXPIRY | true | true | 60 |
| PLAN_LIMIT | true | true | null |
| SYSTEM | true | true | null |

## 8. 通知ログ

## 8.1 notification_log

通知ごとに履歴を保存する。

| 項目 | 内容 |
|---|---|
| notification_type | 通知種別 |
| target_type | 対象種別 |
| target_id | 対象ID |
| recipient | 送信先 |
| subject | 件名 |
| status | PENDING / SENT / FAILED / SKIPPED |
| sent_at | 送信日時 |
| error_message | 失敗理由 |

## 8.2 ステータス遷移

```text
PENDING -> SENT
PENDING -> FAILED
PENDING -> SKIPPED
FAILED  -> SENT    ※再送成功時
```

## 9. 重複送信防止

## 9.1 判定キー

以下が同一の場合、送信済みとみなす。

| 項目 | 内容 |
|---|---|
| tenant_id | テナントID |
| notification_type | 通知種別 |
| target_type | 対象種別 |
| target_id | 対象ID |
| recipient | 宛先 |
| status | SENT |

## 9.2 保守期限通知の再通知方針

初期リリースでは、同一契約・同一宛先への保守期限通知は1回のみとする。

将来的には、60日前、30日前、7日前、当日のような段階通知に対応する。

## 10. スケジューラ仕様

## 10.1 保守期限通知バッチ

| 項目 | 内容 |
|---|---|
| ジョブ名 | MaintenanceExpiryNotificationJob |
| 実行頻度 | 毎日 |
| 実行時刻 | 09:00 |
| 対象 | 有効テナントすべて |
| 失敗時 | 対象通知のみFAILED、処理継続 |

```java
@Scheduled(cron = "0 0 9 * * *")
public void execute() {
    maintenanceNotificationService.notifyExpiringContracts();
}
```

## 10.2 プラン上限警告バッチ

| 項目 | 内容 |
|---|---|
| ジョブ名 | PlanLimitWarningNotificationJob |
| 実行頻度 | 毎日 |
| 実行時刻 | 09:30 |
| 対象 | 有効テナントすべて |

## 11. メール送信仕様

## 11.1 送信方式

- Spring Mailを利用する。
- SMTP設定は環境変数または設定ファイルで管理する。
- 認証情報はソースコードに含めない。

## 11.2 送信元

| 項目 | 内容 |
|---|---|
| From | no-reply@example.com |
| 表示名 | DCIM Notification |

実際のドメインは本番環境決定時に設定する。

## 11.3 送信失敗時

| 失敗内容 | 処理 |
|---|---|
| 宛先不正 | FAILEDとして記録 |
| SMTP接続失敗 | FAILEDとして記録し、後続処理継続 |
| 一時的失敗 | 将来、再送キューを検討 |

## 12. 通知先決定ロジック

### 12.1 保守期限通知

優先順は以下とする。

1. 保守契約に紐付く連絡先
2. 対象データセンターの連絡先
3. テナント管理者

### 12.2 プラン上限警告

- テナント管理者ロールのユーザー

## 13. セキュリティ・個人情報配慮

- メール本文に不要な個人情報や機密情報を含めない。
- APIキー、認証情報、内部IDは通知しない。
- 機器情報は必要最小限にする。
- 宛先不正による情報漏えいを避けるため、連絡先メール変更時は入力チェックを行う。

## 14. CSV連携通知・履歴連携

- CSVエクスポート完了通知は初期必須ではないが、出力履歴は保存する。
- CSVインポートは初期追加対象として、成功・失敗・一部失敗を履歴に残す。
- 将来的に大量取込を非同期化する場合は、取込完了メール通知を追加検討する。

## 15. 運用確認項目

| 項目 | 確認内容 |
|---|---|
| 通知ログ | SENT / FAILED の件数 |
| 失敗理由 | SMTPエラー、宛先不正 |
| 重複通知 | 同一契約に複数回送信されていないか |
| 通知先 | 管理者・連絡先に正しく送信されているか |

## 16. テスト観点

| テスト | 内容 |
|---|---|
| 60日前通知 | 終了日60日前の契約が通知対象になること |
| 対象外契約 | notification_enabled=falseは通知されないこと |
| 重複抑止 | 送信済みログがある場合、再送されないこと |
| 送信失敗 | FAILEDとして記録され、後続処理が継続されること |
| 通知先決定 | 契約連絡先、DC連絡先、管理者の優先順が正しいこと |
