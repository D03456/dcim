# 4. 詳細設計 - 通知処理仕様

## 1. 目的

本書は、Data Center Asset & Infrastructure Manager における通知処理の仕様を定義する。

主な対象は、保守契約期限切れ前通知、プラン上限警告/到達通知、Freeトライアル期限通知、ユーザー招待、パスワード再設定、操作エラー通知、システム通知である。

## 2. 通知種別

| 通知種別 | コード | 概要 | 初期状態 |
|---|---|---|---|
| 保守期限通知 | MAINTENANCE_EXPIRY | 保守契約終了前・当日・期限切れを通知する | 有効 |
| プラン上限警告 | PLAN_LIMIT | 使用量が上限に近づいた場合に通知する | 有効 |
| Freeトライアル期限通知 | TRIAL_EXPIRY | Freeプランの期限到来前または期限到来時に通知する | 有効 |
| パスワード再設定通知 | PASSWORD_RESET | パスワード再設定URLをメール送信する | 有効 |
| ユーザー招待通知 | USER_INVITATION | 招待承諾URLをメール送信する | 有効 |
| 操作エラー通知 | OPERATION_ERROR | CSV取込や外部連携などの失敗を通知する | 有効 |
| システム通知 | SYSTEM | 管理者向けのお知らせ | 有効 |

## 3. 通知チャネル

初期リリースではメール通知と画面内通知を基本とする。画面内通知はVaadin画面上の通知一覧・未読表示として実装し、外部チャネル連携は将来拡張とする。

| チャネル | 対応方針 |
|---|---|
| メール | 初期対応 |
| 画面内通知 | 初期対応 |
| Slack / Teams | 将来対応 |
| Webhook | 将来対応 |

## 4. 通知対象者

| 通知種別 | 対象者 |
|---|---|
| 保守期限通知 | テナント管理者、運用管理者、編集者、保守契約連絡先 |
| プラン上限警告/到達通知 | テナント管理者、契約管理者 |

| システム通知 | テナント管理者 |

## 5. 保守期限通知仕様

## 5.1 概要

保守契約の終了日が近づいた場合、対象テナントの管理者または設定された連絡先へ通知する。

標準は「保守切れ2か月前」、つまり60日前通知とする。

## 5.2 抽出条件

| 条件 | 内容 |
|---|---|
| notification_enabled | true |
| deleted | false |
| end_date | 期限前/当日通知では現在日付以降、期限切れ通知では現在日付より前も対象 |
| 通知対象日 | `end_date - notification_days_before <= 現在日付` |
| 重複送信 | 同一対象・同一通知種別・同一宛先に送信済みでない |

## 5.3 標準通知タイミング

| タイミング | 内容 |
|---|---|
| 60日前 | 標準通知。初期必須 |
| 30日前 | 追加通知。初期重要 |
| 当日 | 期限到達通知。初期重要 |
| 期限切れ翌日以降 | 期限切れ通知。初期必須 |
| 7日前 | 将来オプション |

## 5.4 処理フロー

```text
1. スケジューラが日次で起動
2. 有効なテナントを取得
3. テナントごとの通知設定を取得
4. 保守期限が近い契約を抽出
5. 対象契約に紐付く機器を取得
6. 通知先を決定
7. 重複通知済みでないか確認
8. 通知チャネルごとに通知ログをPENDINGで作成
9. 画面内通知は受信ユーザー向けに作成し、未読状態で保持
10. メール通知はメール送信処理へ依頼
11. 成功時はSENT、失敗時はFAILEDに更新
```

## 5.5 通知文面例

### 件名

```text
【DCIM】保守契約期限が近づいています：{contractName}
```

### 本文

```text
以下の保守契約の期限が近づいています。

契約名：{contractName}
保守ベンダー：{vendorName}
契約番号：{contractNumber}
契約終了日：{endDate}
対象機器数：{deviceCount}

対象機器：
{deviceList}

必要に応じて、保守更新または機器の確認を行ってください。
```

## 6. プラン上限警告通知仕様

## 6.1 概要

テナントの利用量が契約プラン上限に近づいた場合、管理者へ通知する。

## 6.2 警告条件

| 対象 | 通知条件 |
|---|---|
| データセンター | 使用率80%以上 |
| ラック | 使用率80%以上 |
| 機器 | 使用率80%以上 |
| 管理対象IP数 | 使用率80%以上 |
| ユーザー | 使用率80%以上 |
| タグ | 使用率80%以上 |

## 6.3 通知抑止

- 同一対象のプラン上限警告は、原則1日1回までとする。
- 使用率80%以上でWARNING通知、100%以上でREACHED通知を送信する。
- 100%到達通知は同一対象・同一テナントにつき1日1回までとし、80%警告とは別レベルとして重複抑止する。


## 6.4 Freeトライアル期限通知仕様

### 概要

Freeプランのトライアル期限が近づいた場合、または期限日に到達した場合、対象テナントの管理者・契約管理者へ通知する。

### 抽出条件

| 条件 | 内容 |
|---|---|
| plan_code | FREE |
| tenant.status | ACTIVE |
| trial_end_date | 現在日付 + days_before 以内、または現在日付以前 |
| 重複送信 | 同一テナント・同一通知種別・同一宛先に同日送信済みでない |

### 標準通知タイミング

| タイミング | 内容 |
|---|---|
| 3日前 | 標準通知 |
| 期限日 | 期限到達通知 |

期限超過後は `TRIAL_EXPIRED` として扱い、ログイン・参照・CSVエクスポート・契約プラン確認・有料プラン変更のみ許可する。登録・更新・削除・CSVインポート・ユーザー招待は不可とする。

## 7. 通知設定

## 7.1 notification_setting

| 項目 | 内容 |
|---|---|
| tenant_id | テナントID |
| notification_type | 通知種別 |
| enabled | 通知有効フラグ |
| email_enabled | メール有効フラグ |
| in_app_enabled | 画面内通知有効フラグ |
| days_before | 期限前日数 |

## 7.2 初期設定

| 通知種別 | enabled | email_enabled | in_app_enabled | days_before |
|---|:---:|:---:|:---:|---:|
| MAINTENANCE_EXPIRY | true | true | true | 60 |
| PLAN_LIMIT | true | true | true | null |
| TRIAL_EXPIRY | true | true | true | 3 |
| PASSWORD_RESET | true | true | false | null |
| USER_INVITATION | true | true | false | null |
| OPERATION_ERROR | true | true | true | null |
| SYSTEM | true | true | true | null |

## 8. 通知ログ

## 8.1 notification_log

通知ごとに履歴を保存する。

| 項目 | 内容 |
|---|---|
| notification_type | 通知種別 |
| channel | EMAIL / IN_APP |
| target_type | 対象種別 |
| target_id | 対象ID |
| recipient | 送信先メールアドレス。画面内通知ではNULL可 |
| recipient_user_id | 画面内通知の受信ユーザーID |
| subject | 件名 |
| status | PENDING / SENT / FAILED / SKIPPED |
| sent_at | 送信日時 |
| read_at | 画面内通知の既読日時 |
| error_message | 失敗理由 |

## 8.2 ステータス遷移

```text
PENDING -> SENT
PENDING -> FAILED
PENDING -> SKIPPED
FAILED  -> SENT    ※再送成功時
```

## 9. 重複送信防止

## 9.1 判定キー

以下が同一の場合、送信済みとみなす。

| 項目 | 内容 |
|---|---|
| tenant_id | テナントID |
| notification_type | 通知種別 |
| channel | EMAIL / IN_APP |
| target_type | 対象種別 |
| target_id | 対象ID |
| recipient | メール通知の宛先。EMAILの場合に利用 |
| recipient_user_id | 画面内通知の受信ユーザー。IN_APPの場合に利用 |
| status | SENT |

## 9.2 保守期限通知の再通知方針

初期リリースでは、同一契約・同一通知タイミング・同一チャネル・同一宛先への保守期限通知は1回のみとする。

60日前、30日前、当日、期限切れ通知は初期対応範囲とする。将来的には7日前などの追加段階通知に対応する。

## 11. メール送信仕様

## 11.1 送信方式

- Spring Mailを利用する。
- SMTP設定は環境変数または設定ファイルで管理する。
- 認証情報はソースコードに含めない。

## 11.2 送信元

| 項目 | 内容 |
|---|---|
| From | no-reply@example.com |
| 表示名 | DCIM Notification |

実際のドメインは本番環境決定時に設定する。

## 11.3 送信失敗時

| 失敗内容 | 処理 |
|---|---|
| 宛先不正 | FAILEDとして記録 |
| SMTP接続失敗 | FAILEDとして記録し、後続処理継続 |
| 一時的失敗 | 将来、再送キューを検討 |

## 12. 通知先決定ロジック

### 12.1 保守期限通知

以下を通知対象とする。重複する宛先は1件にまとめる。

1. 保守契約に紐付く連絡先
2. テナント管理者ロールのユーザー
3. 運用管理者ロールのユーザー
4. 編集者ロールのユーザー

DC連絡先・機器担当者は初期通知対象には含めない。必要になった場合は将来拡張で追加する。

### 12.2 プラン上限警告/到達通知

- テナント管理者ロールのユーザー
- 契約管理者ロールのユーザー

画面内通知では `recipient_user_id` に対象ユーザーIDを設定する。メール通知では `recipient` にメールアドレスを設定する。

### 12.3 Freeトライアル期限通知

- テナント管理者ロールのユーザー
- 契約管理者ロールのユーザー

画面内通知では `recipient_user_id` に対象ユーザーIDを設定する。メール通知では `recipient` にメールアドレスを設定する。

## 13. セキュリティ・個人情報配慮

- メール本文に不要な個人情報や機密情報を含めない。
- APIキー、認証情報、内部IDは通知しない。
- 機器情報は必要最小限にする。
- 宛先不正による情報漏えいを避けるため、連絡先メール変更時は入力チェックを行う。

## 14. CSV連携通知・履歴連携

- CSVエクスポート完了通知は初期必須ではないが、出力履歴は保存する。
- CSVインポートは初期追加対象として、成功・失敗・一部失敗を履歴に残す。
- 将来的に大量取込を非同期化する場合は、取込完了メール通知を追加検討する。

## 15. 運用確認項目

| 項目 | 確認内容 |
|---|---|
| 通知ログ | SENT / FAILED の件数 |
| 失敗理由 | SMTPエラー、宛先不正 |
| 重複通知 | 同一契約に複数回送信されていないか |
| 通知先 | 管理者・連絡先に正しく送信されているか |

## 16. テスト観点

| テスト | 内容 |
|---|---|
| 保守期限通知 | 終了日60日前、30日前、当日、期限切れの契約が通知対象になること |
| 画面内通知 | 受信ユーザー単位で未読通知が作成され、既読化できること |
| 対象外契約 | notification_enabled=falseは通知されないこと |
| 重複抑止 | チャネル・宛先単位で送信済みログがある場合、再送されないこと |
| 送信失敗 | FAILEDとして記録され、後続処理が継続されること |
| 通知先決定 | 保守契約連絡先、テナント管理者、運用管理者、編集者が対象になり、DC連絡先・機器担当者が初期対象外であること |
| Free期限通知 | 期限3日前・期限日に通知対象になること |
| Free期限通知重複抑止 | 同一テナント・同一宛先に同日重複送信されないこと |
| プラン上限通知 | 管理対象IP数を含む対象で80%警告・100%到達通知が送信されること |
| 招待/操作エラー通知 | USER_INVITATION と OPERATION_ERROR が通知ログに残ること |
