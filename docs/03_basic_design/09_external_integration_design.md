# 外部連携設計

## 1. 目的

本書は、本システムの外部連携方針を定義する。

初期リリースではメール通知とCSV入出力を中心とし、クラウドAPI連携、Webhook、チャット通知は将来拡張として扱う。

## 2. 外部連携一覧

| 区分 | 連携先 | 用途 | 初期対象 |
|---|---|---|:---:|
| メール | SMTP / メール送信サービス | 保守期限通知、プラン上限警告、操作エラー通知、システム通知、招待/パスワード再設定 | ○ |
| CSVエクスポート | ブラウザダウンロード | データ持ち出し、台帳共有 | ○ |
| CSVインポート | ブラウザアップロード | 初期データ登録、台帳移行 | △ |
| クラウドAPI | AWS等 | クラウド資産の自動取込 | 将来 |
| Webhook | 外部システム | 通知・イベント連携 | 将来 |
| Slack / Teams | チャット | 通知連携 | 将来 |

## 3. メール送信設計

## 3.1 メール用途

| 用途 | 通知種別 | 対象者 |
|---|---|---|
| 保守期限通知 | MAINTENANCE_EXPIRY | テナント管理者、運用管理者、編集者、保守契約連絡先 |
| プラン上限警告 | PLAN_LIMIT | テナント管理者、契約管理者 |
| 操作エラー通知 | OPERATION_ERROR | 実行者、テナント管理者、必要に応じてシステム管理者 |
| システム通知 | SYSTEM | テナント管理者 |
| Free期限通知 | TRIAL_EXPIRY | テナント管理者、契約管理者 |
| ユーザー招待 | USER_INVITATION | 招待対象メールアドレス |
| パスワード再設定 | PASSWORD_RESET | 再設定依頼ユーザー |

## 3.2 送信方式

- Spring Mailを利用する。
- SMTP接続情報は環境変数または秘密情報管理で扱う。
- メール送信結果は通知ログに保存する。
- ユーザー招待メールは `USER_INVITATION` テンプレートを使用し、招待承諾URL、有効期限、問い合わせ先を含める。平文トークンは保存せず、送信履歴とトークンハッシュを保持する。
- 招待メールの再送は旧トークンを取消して新トークンを発行する。取消済み・使用済み・期限切れトークンは承諾不可とする。
- 一時的な送信失敗は将来再送キューを検討する。

## 3.3 メール送信エラー対応

| エラー | 対応 |
|---|---|
| 宛先不正 | FAILEDとして記録し、対象宛先をスキップ |
| SMTP認証失敗 | バッチ全体または通知処理を失敗扱いにし、管理者通知 |
| 一時的な接続失敗 | FAILEDとして記録。将来再送対象 |

## 3.4 操作エラー通知

操作エラー通知は `OPERATION_ERROR` として、一般的な `SYSTEM` 通知とは分離する。

| 対象イベント | 通知先 | チャネル | 遷移先/補足 |
|---|---|---|---|
| CSV取込失敗・行エラー閾値超過 | 実行者、テナント管理者 | 画面内通知、必要に応じてメール | CSV取込履歴・行エラー詳細 |
| メール送信失敗 | テナント管理者、システム管理者 | 画面内通知、運用メール | 通知ログ詳細 |
| 外部連携失敗 | テナント管理者、運用管理者 | 画面内通知、必要に応じてメール | 連携設定または将来拡張の連携履歴 |
| バッチ処理失敗 | テナント管理者、システム管理者 | 画面内通知、運用メール | バッチログ・再実行手順 |

通知ログには、通知種別、対象種別、対象ID、発生元処理、エラー概要、再実行要否、チャネル別送信結果を記録する。同一原因の連続失敗は、対象・通知先・チャネル単位で重複抑止または集約する。

## 4. CSV連携設計

## 4.1 CSVエクスポート

| 項目 | 方針 |
|---|---|
| 初期対象 | データセンター、ラック、機器、IPサブネット/IP利用状況、保守契約、保守未加入機器一覧、保守期限接近一覧 |
| 権限 | 閲覧権限があり、CSV_EXPORTが許可されたデータのみ出力可能。契約管理者はリソース詳細CSVを出力不可 |
| テナント分離 | ログインユーザーのtenant_id配下のみ出力 |
| 履歴 | `csv_export_history` に出力履歴を保存 |
| 文字コード | 初期はExcel利用を考慮してUTF-8 BOM付きCSVを基本とする |

## 4.2 CSVインポート

| 項目 | 方針 |
|---|---|
| 初期位置づけ | 初期追加対象。初期リリースでは画面/API/権限を無効化し、初期追加フェーズで有効化する。Freeプランは1ファイル100行まで |
| 初期追加対象 | データセンター、ラック、機器、IPサブネット/IP利用状況、保守契約 |
| 権限 | 初期追加フェーズでテナント管理者、運用管理者、編集者が実行可能 |
| 検証 | ヘッダ、必須、形式、参照存在、プラン上限 |
| 履歴 | `csv_import_history`、`csv_import_error` に保存 |


## 4.3 CSVエクスポート対象

| ID | 対象 | 初期対象 |
|---|---|:---:|
| CSV-OUT-001 | データセンター一覧 | ○ |
| CSV-OUT-002 | ラック一覧 | ○ |
| CSV-OUT-003 | 機器一覧 | ○ |
| CSV-OUT-004 | IPサブネット/IP利用状況 | ○ |
| CSV-OUT-005 | 保守契約一覧 | ○ |
| CSV-OUT-006 | 保守未加入機器一覧 | ○ |
| CSV-OUT-007 | 保守期限接近一覧 | ○ |

## 4.4 CSVエクスポート項目制御

CSV出力は画面別・ロール別に許可する。個人情報、認証情報、トークン、秘密情報は出力対象外またはマスキングする。契約管理者は契約・利用状況の集計確認に必要な項目のみ画面で参照でき、リソース詳細CSVは出力できない。

## 5. クラウドAPI連携（将来拡張）

| 項目 | 方針 |
|---|---|
| 対象 | AWSアカウント、EC2、EKS、コンテナ等 |
| 初期リリース | 対象外 |
| 認証情報 | 暗号化または秘密情報管理で扱う |
| 同期方式 | 定期同期、手動同期を検討 |
| 注意 | クラウドリソースを機器数上限に含めるかは将来決定 |

## 6. セキュリティ方針

- APIキー、SMTPパスワード、クラウド認証情報はDB平文保存しない。
- CSV出力は権限とテナント分離を必ず適用する。
- CSVインポート時は他テナントIDを指定されても無視またはエラーにする。
- メール本文には不要な個人情報・認証情報・内部IDを含めない。

## 7. 後続確認事項

| 項目 | 確認内容 |
|---|---|
| SMTPサービス | 本番で利用するメール送信サービス |
| CSV文字コード | 初期はUTF-8 BOM付きCSVを基本とする。必要に応じて運用設計で補足 |
| CSV初期対象 | データセンター、ラック、機器、IPサブネット/IP利用状況、保守契約に決定済み |
| クラウド連携時期 | 将来拡張フェーズで決定する |

## 付録A. Issue対応追補: 通知対象・CSV出力

### A.1 メール通知対象と画面内通知対象

保守契約連絡先はユーザーアカウントとは限らないため、通知種別ごとにメール対象と画面内通知対象を分離する。

| 通知種別 | メール対象 | 画面内通知対象 |
|---|---|---|
| 保守期限通知 | テナント管理者、運用管理者、編集者、保守契約連絡先 | テナント管理者、運用管理者、編集者 |
| プラン上限通知 | テナント管理者、契約管理者 | テナント管理者、契約管理者 |
| 操作エラー通知 | 発生元別通知先 | ユーザーアカウントを持つ対象者のみ |
| 招待/再設定 | 対象メールアドレス | なし |

### A.2 CSVエクスポート方式

CSV出力は、件数が少ない場合は同期ダウンロード、件数が多い場合は非同期生成後に履歴画面からダウンロードする。再ダウンロード時も対象画面の閲覧権限と `PERM_CSV_EXPORT` を再確認する。一時ファイルには有効期限を設け、期限切れ後は再生成を促す。

### A.3 プラン上限通知

プラン上限通知は WARNING / REACHED / EXCEEDED の通知レベルを持つ。改善時は抑止状態を解除し、再度80%以上になった場合に通知できるようにする。
