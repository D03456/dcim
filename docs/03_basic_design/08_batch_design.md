# バッチ設計

## 1. 目的

本書は、本システムの初期リリースに必要な定期処理・非同期処理の方針を定義する。

対象は、保守期限通知、プラン上限警告、Freeトライアル期限確認、CSV処理、バックアップ、データ整理である。

## 2. バッチ一覧

| ID | バッチ名 | 概要 | 初期対象 |
|---|---|---|:---:|
| B-001 | 保守期限通知バッチ | 保守契約の終了日が近い場合にメール通知と画面内通知を作成する | ○ |
| B-002 | プラン上限警告バッチ | 利用量が上限に近づいた場合に管理者へ通知する | ○ |
| B-003 | Freeトライアル期限確認バッチ | Freeプランの期限到来・期限超過を検知する | ○ |
| B-004 | CSVインポート処理 | CSV取込を検証・登録し、履歴を保存する | △ |
| B-005 | CSV一時ファイル整理バッチ | 一時ファイルを削除する | ○ |
| B-006 | DBバックアップバッチ | DBバックアップを取得する | ○ |
| B-007 | 通知ログ整理バッチ | 古い通知ログの整理・保持期間管理を行う | ○ |
| B-008 | 操作履歴整理バッチ | 初期必須の操作履歴保持期間を管理する | ○ |
| B-009 | クラウド同期バッチ | AWS等のクラウド資産を同期する | 将来 |

凡例: ○=初期必須、△=初期追加対象または簡易対応、将来=初期対象外

## 3. バッチ詳細

## 3.1 B-001 保守期限通知バッチ

| 項目 | 内容 |
|---|---|
| 実行頻度 | 毎日 |
| 実行時刻 | 09:00 |
| 対象 | `notification_enabled = true` の保守契約 |
| 条件 | `end_date` が60日前、30日前、当日、または期限切れ再通知対象日。期限切れ契約も対象に含める |
| 通知先 | テナント管理者、運用管理者、編集者、保守契約連絡先。DC連絡先と機器担当者は初期通知先には含めず、将来拡張で検討 |
| 重複抑止 | `notification_type`、`channel`、対象契約、通知タイミング、宛先または`recipient_user_id`単位の送信済みログを確認。期限切れ再通知は7日単位の通知タイミングをキーにする |
| 失敗時 | 対象通知のみFAILEDとして後続処理を継続。画面内通知作成済みでメール送信のみ失敗した場合はチャネル単位で状態を記録 |


### 3.1.1 期限切れ再通知条件

| 項目 | 方針 |
|---|---|
| 初回期限切れ通知 | `end_date` の翌日または期限切れ判定日の初回バッチで送信する |
| 再通知周期 | 初回期限切れ通知後、7日ごとに再通知する |
| 停止条件 | 保守契約の更新状態が `RENEWED` または `TERMINATED`、通知無効化、契約削除、終了日の更新で期限切れでなくなった場合 |
| 通知ログキー | `notification_type=MAINTENANCE_EXPIRY`、`timing_code=EXPIRED`、対象契約、チャネル、宛先、再通知周期開始日またはreference_date |

## 3.2 B-002 プラン上限警告バッチ

| 項目 | 内容 |
|---|---|
| 実行頻度 | 毎日 |
| 実行時刻 | 09:30 |
| 対象 | 有効テナント |
| 条件 | DC、ラック、機器、管理対象IP、タグ、ユーザーの使用率80%以上 |
| 通知先 | テナント管理者、契約管理者 |
| 重複抑止 | 同一対象は原則1日1回まで |

## 3.3 B-003 Freeトライアル期限確認バッチ

| 項目 | 内容 |
|---|---|
| 実行頻度 | 毎日 |
| 実行時刻 | 10:00 |
| 対象 | Freeプランのテナント |
| 条件 | `trial_end_date` が3日前、期限日、または現在日付より前。trialDaysは初期値算出にのみ利用し、判定の正本は `trial_end_date` とする |
| 動作 | 期限前通知、期限超過時は `TRIAL_EXPIRED` 扱いとしてログイン・閲覧・CSVエクスポート・契約プラン確認・有料プラン変更申請のみ許可 |
| 許可操作 | ログイン、参照、CSVエクスポート、契約プラン確認、有料プランへの変更申請 |
| 禁止操作 | 登録、更新、削除、CSVインポート、ユーザー招待、オプション追加のみの購入 |

## 3.4 B-004 CSVインポート処理

CSVインポートは初期追加対象とする。初期リリースでは画面/API/権限を無効化し、初期追加フェーズで有効化する場合は以下を基本とする。

| 項目 | 内容 |
|---|---|
| 実行方式 | 小規模ファイルは同期処理、大きいファイルは非同期処理を検討 |
| 履歴 | `csv_import_history` に結果を保存 |
| エラー | `csv_import_error` に行単位エラーを保存 |
| 権限 | 初期追加フェーズでテナント管理者、運用管理者、編集者が実行可能 |
| 上限 | プラン上限を超える場合は登録不可。Freeプランは1ファイル100行までとし、101行以上はファイル単位エラーとする |

## 4. 実行方式

- Spring Schedulerを基本とする。
- 本番で複数台構成にする場合は、同一バッチの多重実行を防止する仕組みを導入する。
- バッチ開始・終了・失敗はログに記録する。
- バッチ処理はテナント単位で分割し、特定テナントの失敗で全体が停止しないようにする。

## 5. エラー時対応

| 種別 | 対応 |
|---|---|
| 対象データ不整合 | 対象レコードをスキップし、エラー記録 |
| メール送信失敗 | 通知ログをFAILEDに更新し、`OPERATION_ERROR` としてテナント管理者/運用管理者へ通知する |
| DB接続失敗 | バッチ全体を失敗として記録し、`OPERATION_ERROR` としてシステム管理者へ通知する |
| CSV行エラー | 行単位でエラー記録し、可能なら他行は継続する。失敗件数が閾値を超える場合は実行者とテナント管理者へ `OPERATION_ERROR` を通知する |
| バックアップ失敗 | `OPERATION_ERROR` としてシステム管理者へ通知し、再実行対象にする |

操作エラー通知は一般的なシステム通知と分離し、対象バッチID、対象日、対象ファイル、エラー概要、再実行要否を通知ログに記録する。同一原因の連続失敗は対象・通知先単位で重複抑止または集約する。

## 6. 後続確認事項

| 項目 | 確認内容 |
|---|---|
| CSVインポートの初期対象 | データセンター、ラック、機器、IPサブネット/IP利用状況、保守契約に決定済み。個別IPはIPサブネット/IP利用状況CSV内で扱う |
| バックアップ保持期間 | 運用設計・リリース準備で決定する |
| バッチ実行基盤 | 初期はSpring Schedulerで開始し、複数台構成時に外部ジョブ管理を再検討する |

## 付録A. Issue対応追補: バッチ判定・履歴・通知条件

### A.1 判定日のタイムゾーン

初期リリースのバッチ判定日は `Asia/Tokyo` のシステム日付を基準とする。保守期限通知、Free期限判定、プラン上限警告はいずれも同一基準日で判定する。

### A.2 バッチ実行履歴

バッチ開始・終了・失敗は `batch_execution_log` 相当へ保存する。ステータスは `STARTED / SUCCESS / PARTIAL_SUCCESS / FAILED / SKIPPED`、再実行要否は `retry_required` で管理する。

### A.3 プラン上限警告

| レベル | 条件 | 通知方針 |
|---|---|---|
| WARNING | 使用率80%以上100%未満 | 1日1回まで通知 |
| REACHED | 使用率100%到達 | 到達時に通知。改善するまで同一レベル再通知を抑止 |
| EXCEEDED | 上限超過状態 | 超過検知時に通知し、継続時は週1回などに集約 |
| RECOVERED | 80%未満へ改善 | 抑止状態を解除。必要なら回復通知 |

対象はDC、ラック、機器、管理対象IP、タグ、ユーザーとする。

## 付録B. Issue対応追補: CSV更新・バックアップ・RECOVERED

### B.1 CSVインポート更新処理

CSVインポートは初期追加フェーズで、新規登録と更新を扱う。対象ごとに突合キーを決め、突合できない行は新規、1件に突合できる行は更新、複数に突合する行はエラーとする。更新不可項目が変更されている場合は行エラーとする。

### B.2 DBバックアップ保持期間

DBバックアップは初期運用では30日保持を正本とする。操作履歴保持期間はプラン別要件に従い、DBバックアップ保持期間とは分離する。

### B.3 RECOVERED通知

`RECOVERED` は初期リリースではユーザー通知を送信せず、通知抑止状態の解除と内部通知ログ記録に使う。将来、回復通知を利用者へ送る場合は通知設定でON/OFF可能にする。
